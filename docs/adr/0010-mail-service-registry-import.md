# Официальный реестр поставляет кандидатов, а не готовую политику допуска

Админка загружает стабильный `https://rkn.gov.ru/opendata/7705846236-InformationDistributor/meta.csv` открытого набора Роскомнадзора `7705846236-InformationDistributor`, обнаруживает указанную там актуальную XML-выгрузку реестра ОРИ и формирует diff кандидатов, связанных с сервисами электронной почты. URL датированного XML не закрепляется в коде: владелец актуальной ссылки — metadata набора. Импорт никогда не включает новые домены автоматически: администратор проверяет связь сервиса с допустимыми email-доменами и явно публикует новую версию, сохраняя источник, дату, хеш, diff и автора решения. Ошибка, пустая выгрузка или массовое удаление записей сохраняют последнюю подтверждённую версию. Сервис в состоянии `approved` принимает новые адреса и обслуживает существующие; `deprecated` запрещает новые привязки, но не перевалидирует сохранённые адреса; `blocked` дополнительно останавливает recovery-отправку из-за подтверждённого юридического или security-инцидента. Импорт может лишь предложить `deprecated`, а `blocked` устанавливается администратором вручную с обязательной причиной и записью в аудите. Политика допуска содержит только явно подтверждённые email-домены: запись в реестре ОРИ, MX, DNS и использование инфраструктуры одобренного сервиса не дают корпоративному домену разрешение автоматически.
