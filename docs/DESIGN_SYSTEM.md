# Anomaly Detector: Design System

Статус: утверждённый визуальный и интеракционный контракт. Визуальная база —
комплект экранов `docs/ui/*-desktop.png` и `docs/ui/*-mobile.png`; фактические
токены и примитивы находятся в `webapp/src/index.css` и
`webapp/src/components/ui`.

Документ определяет устойчивые правила интерфейса. Конкретная игровая механика
остаётся в [GAME_DESIGN_BRIEF.md](GAME_DESIGN_BRIEF.md), пользовательская
терминология — в [RULES_REFERENCE.md](RULES_REFERENCE.md), архитектурное
владение состоянием — в [ARCHITECTURE.md](ARCHITECTURE.md), проверка изменений —
в [UX_CHECKLIST.md](UX_CHECKLIST.md) и [TESTING.md](TESTING.md).

## Принципы интерфейса

- Сначала показывать игроку, что происходит сейчас, затем требуемое действие,
  затем объяснение и вспомогательные данные.
- В одной игровой фазе должен быть один визуально доминирующий следующий шаг.
  Навигация, справка и отмена не конкурируют с ним.
- Необратимое или расходующее ресурс действие требует явного подтверждения с
  точным описанием результата. Переключение режима само по себе не сохраняет,
  не очищает и не отправляет выбор.
- Локальный выбор, сохранённый сервером черновик и окончательно отправленное
  действие — разные состояния и никогда не обозначаются одинаково.
- Серверно принятый результат подтверждается новой серверной версией или
  явной квитанцией, а не только завершением локального запроса.
- Сложность раскрывается постепенно: основной выбор виден сразу, правила,
  история и подробные расчёты доступны по запросу.
- Цвет усиливает смысл, но не является его единственным носителем. Статус
  сопровождается текстом и при необходимости иконкой.
- Референсы помогают сравнивать решения, но не переопределяют визуальный язык,
  терминологию, приватность или правила Anomaly Detector.

## Визуальная идентичность

Тёмная sci-fi тема: орбитальная станция, изучающая неизвестную аномалию.
Тон — grounded corporate sci-fi, без пародии и карикатурно-злых корпораций.

### Цветовая палитра

| Роль | Цвет | Применение |
|---|---|---|
| Фон страницы | `#0a0e1a` (глубокий сине-чёрный) | `--background` |
| Фон карточек/панелей | `#111827` / `oklch(0.205 0 0)` | `--card` |
| Обводка | `oklch(1 0 0 / 10%)` (белый 10%) | `--border` |
| Основной текст | `oklch(0.985 0 0)` (почти белый) | `--foreground` |
| Вторичный текст | `oklch(0.708 0 0)` (серый) | `--muted-foreground` |
| Акцент / Primary | `#38bdf8` (голубой, sky-400) | Кнопки действий, активные слоты |
| Акцент / Success | `#4ade80` (зелёный, green-400) | Успешные тезисы, выигранные контракты |
| Акцент / Warning | `#fbbf24` (жёлтый, amber-400) | Предупреждения |
| Акцент / Danger | `#f87171` (красный, red-400) | Ошибки, неверные тезисы |

Текущая тема уже задаёт глубокий сине-чёрный фон и голубой primary в
`webapp/src/index.css`:

```css
.dark {
  --background: oklch(0.12 0.02 260); /* глубокий сине-чёрный */
  /* остальные семантические токены определены рядом */
}
```

Primary для действий и активных состояний:

```css
.dark {
  --primary: oklch(0.65 0.15 230);   /* sky-400 ~ #38bdf8 */
  --primary-foreground: oklch(0.15 0.02 260);
}
```

Компоненты и feature CSS используют семантические токены (`--background`,
`--card`, `--primary`, `--destructive`), а не повторяют значения цветов.

### Типографика

- Шрифт: Figtree Variable (уже подключён)
- Заголовки панелей: `h5`/`h6`, uppercase, tracking-wide
- Основной текст: `body`/`bodySm`
- Моноширинный: ID комнаты, коды слотов

### Иконография

- Каждый результат теста (transmission gain, attenuation, reflection, unstable collapse) имеет:
  - Уникальный цвет
  - Уникальную иконку
  - Короткий текст
- Цвет никогда не является единственным носителем смысла

## Layout

### Mobile-first (портрет)

Одна колонка, фазы — полноэкранные секции с вертикальным скроллом.
Таймер и текущая фаза всегда видны (sticky header).

- Интерактивные цели соответствуют минимуму WCAG 2.2 AA по размеру или
  интервалу. Увеличенная область для частых и критичных действий выбирается
  после проверки плотности и ошибок ввода, а не назначается всем контролам
  автоматически.
- При недостатке ширины меняется иерархия и композиция, а не только размер
  шрифта; основной CTA и статус не уходят за горизонтальный скролл.
- Диалог с длинным содержимым может становиться полноэкранной рабочей областью.
- Tooltip и дополнительная информация доступны через фокус или нажатие, а не
  только через hover.

### Desktop

Многоколоночная сетка (две или три колонки в зависимости от контента).

```
┌──────────────────────────────────────────────┐
│  Header: логотип, навигация, профиль         │
├──────────────────────┬───────────────────────┤
│                      │                       │
│  Игровой процесс     │  Результаты раунда    │
│  (слоты, мощность,   │  (таблица игроков,    │
│   фазы действий)     │   анализ модели,      │
│                      │   контракты)          │
│                      │                       │
├──────────────────────┴───────────────────────┤
│  Аудит (после завершения матча)              │
└──────────────────────────────────────────────┘
```

### Зоны

1. **Header** — логотип "Anomaly Detector", навигация, профиль
2. **Левая колонка** — игровой процесс: слоты, мощность, действия текущей фазы
3. **Правая колонка** — результаты, аналитика, контракты
4. **Нижняя зона** — аудит (post-match)

## Компоненты

### Кнопки

- **Primary (действие):** голубой фон (`--primary`), тёмный текст, `size: lg`
- **Secondary (навигация):** прозрачный с обводкой (`variant: outline`)
- **Слоты (01–06):** крупные квадратные кнопки, 6 в ряд на десктопе, сетка 3×2 на мобильном.
  Выбранный слот — голубая заливка. Недоступный — серый с пониженной opacity.
- **Подтвердить:** primary, внизу секции, `size: lg`
- Текст кнопки называет действие и по возможности объект: «Сохранить первую
  пару», «Отправить финальную модель». Общие «ОК» и «Продолжить» не используются
  для значимых решений без поясняющего контекста.
- Во время отправки повторное действие блокируется, но текущий выбор остаётся
  читаемым. После ответа интерфейс показывает принятый результат или путь
  восстановления.

### Панели

- `Card` с заголовком (uppercase) и разделителем
- Нумерация фаз: крупная цифра слева от названия ("3. Распределение мощности")
- Заголовок раунда: "РАУНД 2 / 5"

### Игроки

- Строка: номер слота + никнейм + статус
- В лобби: занятые места — сплошная обводка, свободные — пунктирная, пониженная opacity
- В результатах: таблица с рейтингом, изменением за раунд

### Таймер

- Всегда видимый (sticky)
- Формат: `MM:SS`
- Красный когда осталось <10 секунд
- Истечение времени показывается как серверное состояние, а не как локальная
  догадка клиента. После дедлайна интерфейс синхронизируется и объясняет, какое
  консервативное действие применил сервер.

### Модальные окна и рабочие области

- Заголовок сообщает, какое решение принимается; описание — его последствия.
- Основная и отменяющая кнопки визуально различаются и имеют точные подписи.
- Закрытие не должно неявно подтверждать, очищать или отправлять выбор.
- На мобильном длинная форма или модель может занимать весь экран; при этом
  сохраняются доступные название фазы, таймер и понятный способ возврата.
- Фокус удерживается внутри модального окна и возвращается на элемент,
  открывший его.

### Загрузка, пустые состояния и подсказки

- Индикатор загрузки появляется только когда ожидание заметно; быстрые переходы
  не прерываются декоративным spinner.
- Текст описывает выполняемое действие: «Синхронизируем тендер», а не только
  «Загрузка».
- Skeleton сохраняет ожидаемую геометрию, но не имитирует данные, которые могут
  раскрыть скрытую игровую информацию.
- Пустое состояние объясняет причину и следующий доступный шаг.
- Tooltip краток, не перекрывает объясняемый объект и не содержит критически
  важную информацию, недоступную иным способом.

## Состояния интерфейса

Каждое серверно значимое действие проектируется по общей матрице. Не все
состояния обязаны быть отдельным компонентом, но игрок должен различать их по
тексту и доступным действиям.

| Состояние | Что должен понимать игрок | Требование к интерфейсу |
|---|---|---|
| `loading` | Данные ещё не готовы | Содержательный статус без ложного действия |
| `ready` | Можно выбирать и менять решение | Основной CTA доступен только при валидном выборе |
| `draft-local` | Изменение пока находится только в форме | Не использовать формулировки «сохранено» или «принято» |
| `draft-saved` | Черновик сохранён сервером, но не отправлен | Показать время/статус сохранения и отдельное финальное действие |
| `submitting` | Команда отправляется | Заблокировать дубликат и сохранить видимость выбора |
| `accepted` | Сервер принял конкретное действие | Показать принятую сводку и дальнейший статус |
| `waiting` | Сейчас действует другой игрок или участники | Показать кого/что ожидаем и что уже принято у текущего игрока |
| `conflict` | Представление устарело | Обновить серверное состояние и объяснить, нужно ли повторить выбор |
| `expired` | Серверный дедлайн завершился | Показать применённый результат тайм-аута и новую фазу |
| `reconnecting` | Связь потеряна, локальное представление может устареть | Заблокировать рискованные команды, не скрывать причину |
| `recovered` | Актуальное состояние восстановлено | Явно показать, что сохранено, отправлено и ещё доступно |
| `completed` | Действие или тендер окончательно завершены | Не показывать элементы, создающие впечатление редактирования |

Статусы ошибки делятся на исправимые пользователем, временные и окончательные.
Сообщение всегда содержит следующий полезный шаг: исправить ввод, повторить,
обновить состояние или продолжить в новой фазе.

### Pre-game (лобби)

- Создание комнаты: выбор capacity (2/3/4) + кнопка "Создать команду"
- Лобби: room ID для копирования, список игроков с личным управлением готовностью, кнопка старта (только хост, только при полной комнате и готовности всех игроков)
- Вход по коду: поле ввода room ID + кнопка "Войти по коду"
- Навигация: "Мои матчи", "Профиль"

### Active game

- **Выбор слота:** 6 кнопок (01–06), выбранный слот подсвечен голубым, подтверждение
- **Распределение мощности:** 4 категории (Разведка, Лаборатория, Анализ моделей, Контракты) с выбором 0/1/2, порядок от раннего слота к позднему
- **Разведка:** явный выбор Неизвестного сектора или известного Сигнала и
  отдельное подтверждение исследования
- **Фазы раунда:** выбор слота доступа → распределение мощности → разведка →
  лаборатория → анализ модели → контракты
- **Завершение тендера:** отдельная общая фаза финальной научной модели, затем
  завершённый аудит
- Фазы показываются согласно сохранённому `Tender Ruleset`; развёртывание новой
  версии интерфейса не меняет механику уже созданного тендера.
- Публичные результаты помечаются «Видят все», приватные измерения и тезисы —
  «Только вы». Приватное состояние не используется в чужих строках, ожидании
  или публичном журнале.

### Post-game (аудит)

- Полная таблица результатов
- Раскрытие скрытой конфигурации аномалии
- Кнопка "Показать аудит" на странице истории матчей

### Профиль

- Никнейм, локализация (ru/en), история матчей
- Кнопка удаления аккаунта

## Что исключено из MVP

- Чат
- Быстрая игра / matchmaking
- Поиск команд
- Восстановление пароля и вход через Telegram
- Ручной переход раундов (автоматический по таймерам)

## Терминология UI

- Кнопка создания комнаты: **"Создать команду"** (не "Создать комнату")
- Вход в комнату: **"Войти по коду"** (не "Присоединиться")
- История: **"Мои матчи"** (не "История матчей")

Все пользовательские строки живут в доменных i18n-чанках. В компонентах не
создаются альтернативные русские формулировки для уже определённых терминов.

## Применение внешних референсов

Перед переносом внешней идеи фиксируются задача, наблюдаемое поведение и причина,
по которой решение подходит Anomaly Detector. Внешний код и стиль не копируются
автоматически.

- Для крупного flow найти несколько реальных примеров, сравнить состояния, а не
  отдельный красивый экран, затем собрать решение из собственных примитивов.
- Компоненты из внешних каталогов используются для прототипа. Новая зависимость
  требует отдельного обоснования; визуальные токены и терминология проекта
  сохраняются.
- Когнитивные эффекты используются как проверяемые UX-гипотезы, а не как способ
  скрыто подтолкнуть игрока или затруднить отказ.
- Ссылка на статью добавляется только после полного чтения, проверки
  применимости к текущему проекту и фиксации конкретного правила, которое она
  обосновывает. Одного заголовка или поискового описания недостаточно. Пока
  такая проверка не проведена, статья не включается в список источников.
